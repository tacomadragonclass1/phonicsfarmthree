## The idea
The child walks Chuck near something. The ONE thing the action would act on
lights up (the "focus"). Pressing the action does that one thing. Nothing is
ever picked up by accident, and the child always sees what will happen.

`CarryRules` owns that decision. It has no rendering and no physics: it is
told where Chuck is each step and answers through events.

```ts
export interface CarryRulesOptions {
  world: WorldQuery;
  blocks: BlockState[];          // live array; entries may be added/removed later
  pedestals: PedestalState[];
  activatables?: Activatable[];  // e.g. a bell
}

export class CarryRules implements EventSource<CarryEvents> {
  constructor(options: CarryRulesOptions);
  readonly carried: BlockState | null;      // getter
  readonly focus: FocusTarget | null;       // getter; what is lit right now
  /**
   * Call once per simulation step.
   * @param position Chuck's feet (bottom-centre), world space.
   * @param heading  unit horizontal direction he is facing/travelling.
   * @param action   true on the step the action was pressed.
   */
  step(position: Vec3, heading: { x: number; z: number }, action: boolean): void;
  /** Forget a carried block without dropping it (it was consumed elsewhere). */
  releaseCarried(): void;
  on(...)  // from EventSource<CarryEvents>
}
```

## Rules
Every `step`, in this order:

### 1. Work out the focus
Candidates, each needing horizontal distance `< interactionDistance` AND
line of sight:
- **Empty hands:** every block that is not carried (loose OR on a pedestal),
  and every activatable.
- **Carrying:** every EMPTY pedestal, and every activatable.
  (Blocks are never candidates while carrying.)

Line of sight for a candidate at position `p` with ids `ignore`:
`world.canReach(chuck + {y: reachFromHeight}, p + {y: reachToHeight}, ignore)`.
For a block, `ignore` = its own id plus the id of the pedestal it sits on
(if any). For a pedestal or an activatable, its own id.

The focus is the NEAREST candidate (horizontal distance), with hysteresis so
it does not flicker: if the previous focus is still a candidate, keep it
unless another candidate is nearer by more than
`PlayerTuning.focusHysteresis`. "Same focus" is judged by kind + id, not by
object identity. If the focus changed (including to/from null), emit
`focusChanged` with the new value. Emit nothing when it did not change.

### 2. If `action` is true, act on it
- Focus is a **block** (hands are empty): if it is on a pedestal, clear both
  references (`pedestal.blockId = null`, `block.pedestalId = null`) and emit
  `removed`. Then `block.carried = true`, emit `pickedUp`.
- Focus is a **pedestal** (carrying): `carried.carried = false`,
  `block.pedestalId = pedestal.id`, `pedestal.blockId = block.id`,
  `block.position = pedestal.position + {y: snapHeight}`, emit `placed`.
- Focus is an **activatable**: call `activate()`. Hands are unchanged.
- No focus and **carrying**: try to **drop** (below).
- No focus and empty hands: nothing happens.
After acting, recompute the focus (step 1 again) so the highlight is right
on the very same step, emitting `focusChanged` if it changed.

### Drop
For each angle in `PlayerTuning.dropAngles` (degrees, in order): rotate
`heading` about +Y by that angle (`rotateY`), scale by `dropDistance`, add
to Chuck's x/z. `g = world.groundHeight(x, z, chuck.y + 0.15)`; if null skip
this spot. The block rests at `rest = g + 0.02`. Skip unless
`world.isBoxClear({x, y: rest + 0.4, z}, dropHalfExtents, [block.id])`.
Skip unless `world.canReach(chuck + {y: 0.4}, {x, y: rest + 0.4, z}, [block.id])`.
First spot that survives: `carried = false`, `position = {x, rest, z}`, emit
`dropped`. If none survives Chuck keeps the block and nothing is emitted.

Only one block can be carried.

## Tests (at least these)
- nothing in reach => focus null, no event; walking into reach emits
  `focusChanged` once, and not again while it stays the focus
- standing next to a block does NOT pick it up without the action
- action on a focused loose block picks it up (`pickedUp`), and the focus
  then becomes whatever is valid while carrying (or null)
- nearest of two blocks is the focus; hysteresis: a second block that is
  nearer by 0.1 does not steal it, nearer by 0.3 does
- a block with no line of sight is never the focus; `ignore` ids include the
  block's own id (assert via the recorded calls)
- carrying: blocks are not candidates; an empty pedestal in reach is;
  an occupied one is not
- place on the focused pedestal: both references set, position at
  snapHeight, `placed` emitted
- empty hands next to an occupied pedestal: the block on it is the focus;
  action emits `removed` then `pickedUp` and clears both references
- activatable in focus: action calls `activate()` both empty-handed and
  while carrying; when a pedestal is nearer than the bell the pedestal wins
- no focus + carrying + action => drop 1.12 m ahead along the heading at
  ground + 0.02; falls back to the 45-degree spot when the front is blocked;
  keeps the block when all eight fail; skips a spot with no ground
- no focus + empty hands + action => nothing
- `releaseCarried` empties the hands with no `dropped` event
