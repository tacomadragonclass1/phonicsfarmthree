## 1. `FollowCameraRig`
Computes where the camera is and what it looks at. It knows nothing about
rendering. Use helpers from `src/core/math.ts`.

```ts
export interface FollowCameraOptions {
  distance?: number;        // 11
  minDistance?: number;     // 3.5
  pitch?: number;           // radians down from horizontal, default 24 deg
  lookHeight?: number;      // 1.0  (above the target's feet)
  lead?: number;            // 1.6  metres at full speed
  leadRate?: number;        // 4    per second
  fullSpeed?: number;       // 6.4  speed at which the lead is full
  deadzone?: number;        // 0.35
  followRate?: number;      // 7.5  per second
  homeYaw?: number;         // 0    world yaw the camera looks ALONG
  yawRange?: number;        // 55 deg either side of home
  yawSpeed?: number;        // 1.6 rad/s at full stick
  yawHomeDelay?: number;    // 2.5 s without input before easing home
  yawHomeRate?: number;     // 2.0 per second
  probeRadius?: number;     // 0.3
  pullInRate?: number;      // 12.5 per second (tau 0.08 s)
  pushOutRate?: number;     // 1.67 per second (tau 0.6 s)
  probe?: CameraProbe;      // optional; without it the path is always clear
}
export interface CameraPose { position: Vec3; lookAt: Vec3; yaw: number; distance: number }

export class FollowCameraRig {
  constructor(options?: FollowCameraOptions);
  /** Jump straight onto the target: no easing, lead 0, yaw = home, full distance. */
  snap(target: Vec3): void;
  /**
   * @param target   the character's feet, world space
   * @param velocity the character's actual velocity (y ignored)
   * @param yawInput camera swing in [-1, 1]; positive swings the view right
   * @param dt       seconds since the last update (real frame time)
   */
  update(target: Vec3, velocity: Vec3, yawInput: number, dt: number): CameraPose;
  readonly pose: CameraPose;            // last computed
  setHomeYaw(yaw: number): void;        // eases there; does not snap
  /** World yaw of "screen up": the direction a push UP the screen walks. */
  readonly forwardYaw: number;
}
```
Validate options in the constructor (`RangeError` for non-finite values,
distance <= 0, minDistance > distance, pitch outside (0, PI/2)).

### Behaviour, in the order `update` applies it
1. First ever `update` without a prior `snap` behaves as `snap` then update.
2. **Lead.** wanted = normalize(velocity.xz) * lead * min(speed/fullSpeed, 1)
   when speed > 0.5, else 0. `leadVec = damp(leadVec, wanted, leadRate, dt)`
   per component.
3. **Focus with deadzone.** gap = target + leadVec - focus (horizontal part).
   If |gap| > deadzone, move focus by
   `(gap - normalize(gap)*deadzone) * (1 - exp(-followRate*dt))`.
   Height has no deadzone: `focus.y = damp(focus.y, target.y, followRate, dt)`.
4. **Yaw.** `offset` is the swing away from home, kept in
   [-yawRange, +yawRange]. If |yawInput| > 0.05:
   `offset += yawInput * yawSpeed * dt`, clamp, reset an idle timer.
   Otherwise the idle timer counts up; once it exceeds `yawHomeDelay`,
   `offset = damp(offset, 0, yawHomeRate, dt)`.
   `yaw = wrapAngle(homeYaw + offset)`. `setHomeYaw` changes `homeYaw`
   gradually: keep a `homeYawTarget` and `dampAngle` toward it at 1.5/s.
5. **Desired position.** lookAt = focus + {y: lookHeight}. The camera sits
   BEHIND the look-at along `yaw`, raised by `pitch`:
   `back = directionFromYaw(yaw)` (the way the camera looks, horizontally);
   `desired = lookAt - back * (cos(pitch) * D) + up * (sin(pitch) * D)`
   computed with D = `distance`.
6. **Collision.** `f = probe.sweep(lookAt, desiredAtFullDistance, probeRadius)`.
   allowed = max(minDistance, f * distance) (minus nothing else).
   If allowed < currentDistance: `currentDistance = damp(currentDistance, allowed, pullInRate, dt)`
   else `damp(..., pushOutRate, dt)`. Recompute the position with
   D = currentDistance.
7. Return the pose (reuse the same objects every frame; do not allocate).

`forwardYaw` is simply the current `yaw`: pushing up the screen walks along
`directionFromYaw(yaw)`, pushing right walks along `directionFromYaw(yaw - PI/2)`.
Export a helper used by the player controller:
```ts
/** Turn a screen-space stick (x right, y DOWN) into a world direction. */
export function screenToWorld(moveX: number, moveY: number, cameraYaw: number): { x: number; z: number }
```
With cameraYaw 0 (camera looking along +Z): (0,-1) -> (0, +1); (1,0) -> (-1, 0).
(Looking along +Z with Y up, screen-right is world -X.) Check this with a
cross product in a comment-free test rather than trusting this sentence.

## 3. Tests
snap puts the camera exactly `distance` from lookAt at the right pitch and
behind along yaw; standing still inside the deadzone does not move focus;
walking builds a lead that saturates near `lead` and decays after stopping;
focus height follows with no deadzone; yaw input clamps at +-yawRange;
after yawHomeDelay with no input the offset decays toward 0 but not before;
a probe returning 0.5 pulls the distance toward 5.5 quickly and a clear
probe lets it relax back slowly (pull-in is faster than push-out); distance
never goes below minDistance even when the probe returns 0; `screenToWorld`
is orthonormal for several yaws and matches the two fixed cases above;
option validation; pose objects are reused between updates.
