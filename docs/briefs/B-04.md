## `InputManager`
`constructor(sources: InputSource[])`
- `sample(): InputState` -- zero a state object, let every source add into
  it, then: limit (moveX, moveY) to length 1, clamp cameraYaw to [-1, 1].
  `action` is true if any source reported it. Returns the same object each
  call (no allocation per step).
- `releaseAll()`, `dispose()`.

## `KeyboardSource(target: EventTargetLike)` (listens for keydown/keyup/blur)
- Walk: `KeyW`/`ArrowUp` => moveY -1, `KeyS`/`ArrowDown` => +1,
  `KeyA`/`ArrowLeft` => moveX -1, `KeyD`/`ArrowRight` => +1. Use
  `event.code`. Opposite keys cancel. Diagonals are NOT normalised here.
- Action: `KeyE` or `Space`, on keydown, ignoring `event.repeat`. Latched
  until the next `sample`, then cleared. Call `preventDefault()` for Space
  and the arrow keys so the page does not scroll.
- Camera: `KeyQ` => cameraYaw -1, `KeyC` => cameraYaw +1 (held, not latched).
  `KeyE` is the action and is never a camera key.
- `blur` => `release()`.

## `GamepadSource(getGamepads: () => ArrayLike<GamepadLike | null>)`
Polls on `sample` (the Gamepad API has no events for sticks).
- Uses the FIRST connected pad whose `mapping === 'standard'`, else the
  first connected pad.
- Left stick axes 0/1 with a radial deadzone of 0.2, rescaled so the edge of
  the deadzone is 0 and full deflection is 1.
- D-pad buttons 12 up, 13 down, 14 left, 15 right add +-1 and override the
  stick when pressed.
- Right stick axis 2 => cameraYaw, deadzone 0.25, rescaled.
- Action: button 0 (A / Cross). Edge-detected against the previous sample;
  true only on the sample where it goes from up to down.
- If the pad disappears between samples (unplugged) the next sample
  contributes nothing and the edge state resets, and a re-plug with the
  button already held must NOT fire an action (treat the first sample after
  a pad appears as establishing the baseline).
- `release()` resets edge state.

## `PointerSource(target: EventTargetLike, options?: { dragRange?: number; tapMs?: number; tapSlop?: number; now?: () => number })`
Listens for pointerdown / pointermove / pointerup / pointercancel. Defaults:
dragRange 110 px, tapMs 320, tapSlop 24 px.
- The FIRST pointer down becomes the walking stick: remember its origin and
  time. Moving it sets move = offset / dragRange (length limited to 1). If
  the offset exceeds dragRange, drag the origin along behind the pointer so
  it stays exactly dragRange away (one long drag keeps steering).
- When the walking pointer lifts: move becomes 0; if it never travelled more
  than tapSlop from its ORIGINAL origin and was down less than tapMs, that
  is a tap => action.
- ANY OTHER pointer that goes down while the walking pointer is held is a
  SECOND finger. If it lifts having moved less than tapSlop => action.
  If it moves more than tapSlop it becomes a camera swing instead:
  cameraYaw = clamp(horizontal offset from its own origin / dragRange, -1, 1)
  while held, 0 after it lifts, and it does NOT fire an action.
- `pointercancel` on the walking pointer => `release()`.
- Action is latched until the next `sample`. Mouse works through the same
  pointer events (pointerType is not inspected).
- `release()` clears both pointers, move, cameraYaw and any latched action.

## Tests (fake event target + fake pads + fake clock, written in the test file)
Keyboard: each direction, cancel, action latch survives exactly one sample,
repeat ignored, blur releases. Gamepad: deadzone and rescale, d-pad
override, action edge, unplug/replug with the button held, standard-mapping
preference. Pointer: drag magnitude and clamp, trailing origin, quick tap,
slow press is not a tap, second-finger tap, second-finger swing gives
cameraYaw and no action, cancel releases. Manager: merge of two sources,
length limit, same object returned.
