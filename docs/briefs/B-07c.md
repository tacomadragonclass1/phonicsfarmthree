## Fix 1 -- `setEnabled` (test fails at "is false against a block" after re-enabling)
A collider re-enabled with `collider.setEnabled(true)` is not seen by scene
queries after a zero-length step. Do not use `collider.setEnabled` at all.
Implement `setEnabled(id, enabled)` by switching the collider's collision
groups: disabled = `collider.setCollisionGroups(0)` (member of nothing, so
no query and no character movement can hit it); enabled = the same groups
value it was created with (store that value in the entry). Then `refresh()`.

## Fix 2 -- walking covers 10.1 m in 2 s instead of ~12.2 m
Raw Rapier moves the capsule a full 6.4 m in one second with these
controller settings (measured), so the loss is in `CharacterBody.move`: it
overwrites `velocity` with the achieved movement and accelerates from that
next step, which slows the ramp-up. Change it to:
- a PRIVATE `intent` vector {x, z} that the acceleration integrates
  (`approach(intent.x, wishX * walkSpeed, acceleration * dt)`, same for z);
- the delta passed to the controller uses `intent.x`, `intent.z` and the
  vertical speed as now;
- the PUBLIC `velocity` is set from the achieved movement / dt, as now;
- after the move, for each horizontal axis: if `|achieved| < 0.5 * |intent|`
  on that axis, set `intent` on that axis to the achieved value (he hit
  something; stop pushing);
- `teleport` zeroes `intent` too.

## Fix 3 -- the lip test's own geometry is wrong
"steps over a 0.15 m lip but not a 0.6 m one" walks 240 steps (about 25 m)
from x = 1 on a ground that ends at x = 20, with a lip that only spans
x = 4..6: he steps up, walks off the far side, then off the edge of the
world. Rewrite only the walking part of that test:
- low lip: walk in a loop of at most 240 steps and STOP as soon as
  `position.x >= 5`; then expect `position.y` to be within 0.03 of 0.15 and
  `position.x >= 5`.
- high step: walk 120 steps; expect `position.x < 4 - 0.25` and
  `position.y < 0.05`.
Do not change any other test or any tolerance.
