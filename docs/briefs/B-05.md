## 1. `PhonemeSequencer` -- pure logic, NO Web Audio types in this file
```ts
/** Plays one clip. Resolves nothing; calls onEnded when the clip finishes
 *  naturally. `stop()` on the returned handle must NOT call onEnded. */
export interface ClipBackend {
  has(key: string): boolean;
  play(key: string, onEnded: () => void): { stop(): void };
}
export class PhonemeSequencer implements SoundPlayer {
  constructor(backend: ClipBackend);
  playSequence(keys: readonly string[]): void;
  stop(): void;
  readonly busy: boolean;
  on(...)
}
```
Implement the `SoundPlayer` semantics in contracts.ts EXACTLY. Details:
- Keys are lowercased before lookup. Unknown keys (`backend.has` false) are
  dropped when the sequence is queued.
- `playSequence` = `stop()` then queue then start the first clip.
- `stop()`: stops the current clip, clears the queue, and emits
  `sequenceCancelled` only if a sequence was active.
- `letterStarted` is emitted right after `backend.play` is called for a clip.
- When the last clip ends: sequence becomes inactive, emit
  `sequenceFinished`. `busy` is false inside that listener.
- A listener may call `playSequence` from inside any event; this must work
  and must not double-play or recurse forever.
- A stale `onEnded` (from a clip that was stopped or replaced) must be
  ignored even if the backend calls it late.

## 2. `AudioEngine` -- the Web Audio `ClipBackend`
```ts
export class AudioEngine implements ClipBackend, Disposable {
  constructor(context?: AudioContext);            // creates one lazily if omitted
  /** Fetch + decode every entry. Rejects with an Error naming the first url
   *  that failed. Never substitutes a clip. */
  load(entries: Record<string, { url: string }>, baseUrl?: string): Promise<void>;
  /** Resume the context. Call from a user gesture. Resolves true if running. */
  unlock(): Promise<boolean>;
  readonly state: AudioContextState;
  has(key: string): boolean;
  play(key: string, onEnded: () => void): { stop(): void };
  dispose(): void;
}
```
- One `GainNode` master (gain 1). Each `play` makes a fresh
  `AudioBufferSourceNode`; `stop()` detaches `onended` first, then stops.
- `play` of an unknown key calls nothing and returns a no-op handle.
- If the context is suspended, `play` still schedules normally (the browser
  will start it once resumed).
- No test for AudioEngine is required (it needs a browser), but it must
  typecheck under the DOM lib and contain no `any`.
