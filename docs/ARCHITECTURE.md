# phonicsfarmthree — architecture

Living document, owned by the architect. Implementation agents work from
briefs and do not edit this file. Last revised 2026-11-11.

This is a new game. It shares a subject (phonics for young children), a cast
(Chuck and Annette) and an art set with an earlier project, and nothing else:
no rule, layout, control scheme or camera is inherited. Every decision below
was made for this game and can be changed for this game.

---

## 1. What the game is

A small, warm, three-dimensional farm village that a child walks around in.
Letters are physical objects in it — chunky blocks you can carry. Sounds are
attached to the letters, not to menus.

**The one rule that is not negotiable:** every time a child handles a letter,
they hear its sound. Everything else serves that.

### Activities (v0 design)

| Activity | What the child does | What it teaches |
|---|---|---|
| **Hear it** | Pick up any letter block; it says its sound. | Letter–sound correspondence. |
| **Build it** | Put blocks on a row of three stumps; ring the bell; hear the sounds in order, then see whether they made a word. | Blending sounds into words (CVC). |
| **Find it** | Annette asks for a sound; the child brings the letter that makes it. | Hearing a sound and recalling its letter. |

Feedback is never punitive: no buzzers, no lives, no timers, nothing lost.

### Open design questions (the owner decides; defaults are marked)

| # | Question | Options |
|---|---|---|
| D1 | How does a child pick things up? | **DECIDED 2026-11-11: (a)** the nearest thing in reach lights up, one action takes it. Rejected: automatic pickup on contact; tap-and-walk. |
| D2 | Touch controls | **DECIDED 2026-11-11: (a)** drag anywhere to walk + one large on-screen action button. Rejected: gestures only; tap-to-go. |
| D3 | Which letters | **(a, default)** all 26 available, activities choose subsets · (b) a curated CVC set only |
| D4 | World shape | **(a, default)** one continuous place, activities are locations in it · (b) separate small scenes chosen from a hub |
| D5 | Look | **(a, default)** painted textures + ink outline + soft toon light · (b) plain soft PBR · (c) something new, after seeing (a) in the slice |

The vertical slice is built so that D1 and D2 are cheap to switch: rules and
input sit behind small interfaces (§3).

## 2. Technology

| Concern | Choice | Reasoning |
|---|---|---|
| Language / build | TypeScript (strict), Vite | Static output with a relative base; drops into any GitHub Pages path. |
| Rendering | three.js `WebGLRenderer` (WebGL2) | Runs on modest classroom hardware; WebGPU not assumed. |
| Physics | Rapier (`@dimforge/rapier3d-compat`) | The game needs a kinematic character with slopes and step-up, a triangle-mesh ground, static shapes, ray casts, overlap tests and a shape cast for the camera. Rapier has exactly these and is deterministic at a fixed step. Nothing is a dynamic body. |
| Animation | `THREE.AnimationMixer` | The characters ship `idle` and `walk` clips. |
| Assets | `GLTFLoader`, plain GLB | Every model is one mesh, one material, one texture under ~1 MB. |
| Letters | Canvas 2D → `CanvasTexture`, cached per letter | Generated at runtime, crisp, uses the bundled font. |
| Audio | Web Audio API directly | A queue of decoded clips; no library needed. |
| Input | Keyboard events, Pointer Events, Gamepad API | Native. One merged `InputState`. |
| UI | Plain DOM + CSS over the canvas | A few large, simple elements. No framework. |
| Unit tests | Vitest in Node | Logic is pure, and Rapier runs in Node. |
| Browser tests | Real browser against the production build + a `window.__pf` debug hook | See `TESTING.md`. |

No ECS, no state library, no scene framework: a handful of classes wired
together in `src/main.ts`.

## 3. Code layout and the dependency rule

```
src/
  core/      contracts.ts, FixedStepLoop, Emitter, math        (no three, no DOM)
  game/      rules and state machines                          (no three, no DOM)
  physics/   Rapier wrapper; implements WorldQuery + CameraProbe
  assets/    manifest, AssetLibrary, look/ (materials, outline, lights)
  world/     layout data, entity views, scene assembly
  camera/    FollowCameraRig (pure maths) + applyRig (three)
  input/     keyboard / gamepad / pointer sources → InputState
  audio/     AudioEngine (Web Audio), PhonemeSequencer (pure)
  ui/        DOM overlay
  main.ts    composition root; owns the loop
```

`core` ← `game` ← everything else. `game/` never imports three.js, Rapier,
the DOM or audio; it reaches the outside through two interfaces in
`core/contracts.ts`: `WorldQuery` (line of sight, ground height, is-this-box-
clear) and `SoundPlayer` (play a sequence of clips, hear when each starts
and when the sequence ends). Views observe game state and decide nothing.

### The frame

```
requestAnimationFrame
  └ FixedStepLoop.tick
      ├ simulate(1/60) × n      input.sample → rules → physics.step
      └ render(alpha, frameDt)  views interpolate → camera → renderer
```

Input is sampled once per simulation step and button presses are latched
until consumed, so a tap shorter than a frame is never lost. Mixers and the
camera run on real frame time.

### Conventions

Metres, seconds, radians. Y up. Characters face local +Z; yaw 0 faces +Z and
`yaw = atan2(x, z)`. **Every yaw in the code is a world yaw** — character
views are never parented under a rotated node.

## 4. Camera

**Goals:** the world reads as a place with depth and a horizon; Chuck stays
prominent; a five-year-old cannot get lost or end up staring at a wall; the
same on touch, gamepad and keyboard.

| Parameter | Value | Reason |
|---|---|---|
| Lens | 32° vertical FOV | Real perspective, but a longish lens so distant letters stay legible. |
| Distance | 11 m | At 1280×800 a block face beside Chuck is ~100 px tall; ~45 px at 25 m. |
| Pitch | 24° down | Sees over a child-height prop without flattening the world into a map. |
| Look-at | 1.0 m above Chuck's feet, plus a lead | Keeps him just below centre. |
| Lead | up to 1.6 m along his velocity | Shows where he is going rather than where he has been. |
| Deadzone | 0.35 m | A nudged character does not shake the whole world. |
| Follow | exponential, 7.5 /s | Frame-rate independent. |

**Yaw is constrained.** Each area has a *home yaw*. The player may swing the
view up to ±55° either side of it; after 2.5 s without camera input it eases
home. The camera never turns by itself to get behind Chuck, because movement
is screen-relative and a self-turning camera changes what "left" means under
a child's thumb. Pitch and distance are not player controls.

**Collision.** A sphere is swept from the look-at point to the desired camera
position against camera-blocking colliders (buildings, ground). On a hit the
distance pulls in fast (τ 0.08 s) and relaxes out slowly (τ 0.6 s), never
below 3.5 m. Tree canopies do not block; an occluding tree fades instead
(later stage).

The rig is pure maths over a `CameraProbe` interface and is unit-tested
without WebGL. All of the numbers above are starting points to be tuned by
looking at the slice.

## 5. Look (default D5-a, to be judged in the slice)

The models carry hand-painted textures with ambient shading baked in. The
default treatment builds on that:

- **Painted material** — toon-banded diffuse over the model's own texture,
  plus a fine world-space grain so large surfaces are not flat fills, plus a
  faint cool rim on upward edges.
- **Ink outline** — an inverted hull offset in clip space by a pixel count,
  so one line weight covers a cottage and a berry alike.
- **Light** — warm low sun, cool sky ambient, one soft shadow map that
  follows the player, light distance fog.
- **Colour** — sRGB output, no tone mapping to start (the textures are
  painted display-referred); adjusted by measuring screenshots, not by eye
  alone.

Known risk: these meshes are modest in polygon count and a perspective
camera at 11 m sees them close. The slice puts the full look in early to
find out whether they hold up or need new modelling.

**Letter blocks are the most important objects on screen:** the lightest
value in the scene (cream faces), dark ink lowercase letters in Fredoka 600
with a single-storey `a`, one letter on five faces, always generated at
runtime.

## 6. Assets

See `ASSET_INVENTORY.md`. Runtime assets live in `public/assets/` and are
listed in one typed manifest (`src/assets/manifest.ts`). A manifest entry
that fails to load raises a visible error naming the file — there is no
placeholder mesh and no substitution.

| Date | Decision | Alternatives rejected |
|---|---|---|
| 2026-11-11 | Standalone repository `phonicsfarmthree`, no shared history or rules with the earlier project | A branch or sub-directory of the earlier repo. |
| 2026-11-11 | Rapier for physics | three-mesh-bvh + hand-written controller; cannon-es. |
| 2026-11-11 | Constrained-yaw follow camera | Free orbit (confusing for small children); auto-follow-behind (changes control mapping). |
| 2026-11-11 | Plain DOM UI, raw Web Audio | UI/audio frameworks — nothing here needs them. |
| 2026-11-11 | Local-model delegation via `opencode run` with a repo config that enables only local providers | Relying on opencode's global config. |
